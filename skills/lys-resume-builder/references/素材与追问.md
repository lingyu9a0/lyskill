# 两轮取证与证据状态

本文件负责把全部原始材料批量恢复为真实经历和证据链，并控制什么时候才需要追问。

## 原始材料直接作为证据来源

旧简历、课程作业、PPT、项目文件、社团总结、兼职记录、作品、截图和聊天原话都是证据来源。

先读取完用户本轮提供的全部材料，再统一提取事实、冲突和缺口。不要采用“读到一条事实—问一次—更新一次—再问下一条”的串行方式。

材料中明确写出、来源可定位、没有冲突且不会造成归属误解的事实，直接记为“材料已支持”。例如课程 PPT 明确记录模拟经营最终现金和库存时，可以保存为课程模拟结果，不需要再问“这个数字是真的吗”。

“材料已支持”表示当前文件有对应内容，不代表第三方独立认证。通过保留来源和场景边界解决这一问题，不靠重复询问用户解决。

## 第一轮：事实取证

首次 Intake 后，批量建立经历母版。每段经历提取：

- 场景和经历性质；
- `source_type`：课程项目／社团项目／个人项目／实习／工作／比赛／兼职／志愿活动等；
- `execution_status`：已落地／部分落地／仅方案／模拟；
- `start_date`；
- `end_date`；
- `duration`；
- 本人角色；
- 本人实际动作；
- 方法、工具或协作方式；
- 结果或交付物；
- 来源和位置；
- 事实归属与证据状态。

`source_type` 与 `execution_status` 必须分开。“没有执行”只说明完成状态，不能据此猜测它一定是课程项目。日期未知时记录“未知”；没有 JD 时不为补齐格式逐条追问。当前投递版需要展示日期时，在生成前一次性批量询问所有入选经历的缺失日期。

第一轮只立即追问三类问题：

1. 材料冲突：不同文件或同一文件对角色、时间、结果有不同写法；
2. 经历性质：答案会决定它是方案、模拟、实际执行还是商业项目；
3. 事实归属：团队结果可能被误写为个人结果，或本人贡献无法区分。

把这三类问题整理成一组短问题一次性询问。不要在没有 JD 时继续追问不影响真实性边界的数字、时长、人数和反馈细节。

## 证据格式

`evidence.md` 每条事实至少保存：

```text
事实：
来源：
归属：
状态：
```

必要时再保存位置、原始表述、场景边界、数字口径和修订关系。

状态只能使用：

- 材料已支持；
- 用户已确认；
- 材料冲突；
- 归属不清；
- 缺失。

默认只有“材料冲突／归属不清／关键缺失”触发追问。

| 状态 | 含义 | 下一步 |
|---|---|---|
| 材料已支持 | 原始材料能够定位支持，且没有冲突 | 直接进入母版，不重复询问 |
| 用户已确认 | 用户对冲突、性质或归属作了明确确认 | 保存确认轮次和原始回答 |
| 材料冲突 | 不同来源无法同时成立 | 批量列出冲突，请用户选择或补充 |
| 归属不清 | 无法判断是本人、团队还是他人成果 | 只问个人部分和团队边界 |
| 缺失 | 当前材料没有关键事实 | 无 JD 时可保留；有 JD 时按核心要求定向追问 |

新解释不能覆盖旧材料。用户纠错时保留新原话、被修订证据 ID、旧版本 ID 和修改原因。

## 第二轮：岗位取证

只有拿到真实 JD 后，才深挖会影响当前简历的证据。

先完成 JD 匹配，再把“有相邻／代理证据、有经历但证据不足、完全缺失”的核心要求合并成一组定向问题。问题必须指向真实场景，不问抽象能力。

例如销售类缺口可从销售、地推、摆摊、拉赞助、社团招新、校园代理、陌生人沟通、商家联系、用户访谈、需求沟通和异议处理中寻找。用户回答后：

1. 把新经历写回 `experience-master.md`；
2. 把事实和来源写回 `evidence.md`；
3. 更新 `job-signals.md`；
4. 重新执行 JD 匹配。

重新匹配必须覆盖整张任务与硬条件表。原先的“未知／当前缺失”按新回答更新为“已确认满足”“已确认缺失”或“仍未知”，不能只在文件末尾追加一段回补结果。

用户确认没有做过、记不清或不愿提供时，记录该结论并停止重复追问。未来准备做的项目不能写成已有经历。

用户回答与问题编号、语义或已有事实明显冲突时，不自行纠正或猜测含义，先做最小澄清。例如回答“1—4 没有，5 做过公众号”，但第 5 题并非公众号经历时，应先确认用户实际对应的是哪一题，再更新证据。

对当前 JD 有判断价值但用户漏答的字段，先记录为未知。只有该字段会直接影响简历表述或硬门槛判断时，再追一问；否则不阻断简历生成。

## 停止条件

- 第一轮：关键冲突、经历性质和归属已经处理，其他细节可等待 JD；
- 第二轮：核心 JD 要求已有足够证据，或用户明确确认没有更多相关经历；
- 连续追问没有产生新事实时停止，不用“再想想”逼迫用户补造经历。
